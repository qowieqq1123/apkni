## 1. 游戏架构总览

```
┌─────────────┐     HTTP       ┌──────────────┐
│  客户端      │──────────────▶│   PHP 配置服   │  ← infoURL / entryURL
│  (Unity)     │◀──────────────│              │
│              │               └──────────────┘
│  Lua 逻辑层  │                    │
│  C# 网络层   │                    ▼
│  NetBitStream│               ┌──────────────┐
│  序列化协议   │◀────TCP─────▶│   Game Server │
└─────────────┘               │  (C#)         │
                               └──────────────┘
```

### 通信方式
- **配置拉取**：HTTP GET（PHP 服务端），JSON 格式
- **游戏通信**：TCP 长连接（WebSocket 可选），自定义二进制协议
- **序列化**：`NetBitStream`（`ReadInt`/`ReadByte`/`ReadString` 原语）
- **消息路由**：2 层寻址 —— `protocel key`（系统号）+ `funcId`（消息号）

## 3. TCP 消息协议

### 3.1 消息结构

每个 TCP 消息由 `NetBitStream` 序列化，消息头由 C# 层自动拼装：

```
TCP 帧 (NetPacket):
  [4 bytes] 总长度 (小端 int32)
  [2 bytes] protocel key (系统号)
  [2 bytes] funcId (消息号)
  [N bytes] 消息体 (ProtocelParams 序列化)
```

### 3.2 Struct ID 范围语义

| 范围 | 用途 | 数量 | 方向 |
|------|------|------|------|
| `10001` – `10999` | RECV 结构体 | **916 个** | 服务端 → 客户端 |
| `11001` – `11999` | SEND 结构体 | **149 个** | 客户端 → 服务端 |
| `3000`+ | GAMEATTR 属性 | 0（本表未使用） | — |

> 来源：`NetWorkProtocolParser` 常量 `STRUCT_RECV_PREFIX=10000`、`STRUCT_SEND_PREFIX=11000`、`GAMEATTR_PREFIX=3000`

### 3.3 消息方向约定

每条 protocel 条目有两个表：

- **Table A**：客户端 → 服务端（C→S），使用 `SEND` 结构体（11000+）
- **Table B**：服务端 → 客户端（S→C），使用 `RECV` 结构体（10000+）

### 3.4 核心登录消息号

| key | funcId | 方向 | 结构体 | 说明 |
|-----|--------|------|--------|------|
| 255 | 1 | C→S | — | 登录请求（4 参数） |
| 255 | 1 | S→C | — | 登录结果（1 参数：result_code） |
| 255 | 2 | C→S | — | 登录验证/续期（5 参数） |
| 255 | 2 | S→C | — | 登录验证结果（3 参数） |
| 255 | 3 | C→S | — | 心跳（1 参数） |
| 255 | 3 | S→C | — | 心跳回复（2 参数） |
| 255 | 4 | C→S | — | 登出（1 参数） |
| 255 | 4 | S→C | — | 登出通知（3 参数） |
| 255 | 5 | C→S | — | 角色请求（5 参数） |
| 255 | 5 | S→C | — | 角色返回（1 参数：result_code） |
| 255 | 9 | C→S | — | ping（1 参数） |
| 255 | 9 | S→C | — | pong（2 参数） |

**Login result_code 含义**：

| code | 含义 |
|------|------|
| 0 | 登录成功 |
| 1 | 密码错误 |
| 2 | 没有这个账号 |
| 3 | 已经在线 |
| 4 | 服务器忙 |
| 5 | 服务器没有开放 |
| 6 | session服务器有问题 |
| 7 | 不存在这个服务器 |
| 8 | 账户纳入防沉迷 |
| 9 | 帐号被封禁 |
| 10 | 帐号托管中 |

## 4. Struct 类型系统

### 4.1 eDataType 枚举

| type 码 | 枚举名 | C# 类型 | 字节数 | 说明 |
|---------|--------|---------|--------|------|
| `0x00` (0) | None | void | 0 | 无类型 |
| `0x01` (1) | Char | sbyte | 1 | 有符号字节 |
| `0x02` (2) | UChar | byte | 1 | 无符号字节 |
| `0x03` (3) | Short | short | 2 | 有符号短整型 |
| `0x04` (4) | UShort | ushort | 2 | 无符号短整型 |
| `0x05` (5) | Int | int | 4 | 有符号整型 |
| `0x06` (6) | UInt | uint | 4 | 无符号整型 |
| `0x07` (7) | Int64 | long | 8 | 有符号长整型 |
| `0x08` (8) | UInt64 | ulong | 8 | 无符号长整型 |
| `0x09` (9) | Float | float | 4 | 浮点数 |
| **`0x0a` (10)** | **String** | **string** | 变长 | **UTF-8 字符串** |
| `0x0b` (11) | Struct | struct | 变长 | 内嵌结构体 |
| **`0x0c` (12)** | **Array** | **array** | 变长 | **数组** |
| `0xff` (255) | EndOfAttr | — | 0 | 属性结束标记 |

### 4.2 类型码细分规则

#### 基础类型（type 0x00-0x09）
直接按对应 C# 类型读写，小端字节序。

#### 字符串（type=0x0a）
```
ReadString 实现：
  读取 u16 LE 长度 n
  n == 0 → 返回空串
  n > 0  → 读 n 字节 UTF-8，再跳过 1 字节 '\0' 终止符
```

#### 内嵌结构体（type=0x0b）
结构体内嵌在其他结构中，由 `typename_id` 引用结构体定义：
```csv
# 例：itemStruct 的 itemData 字段 type=0x0b, tid=10003 → itemDataStruct
10002,itemStruct,5,itemData,0x0b,0,0,10003,0
```

#### 数组（type=0x0c）
数组的每个元素是一个结构体引用，由 `typename_id` 指定元素类型：
```csv
# 例：itemDataStructEquip 的 randattrList 字段 type=0x0c, tid=10530
# 表示一个元素类型为 struct 10530 的数组
10004,itemDataStructEquip,2,randattrList,0x0c,0,0,10530,0
```
数组长度由**前一个字段**（通常是 `len`/`count` 字段）决定。

#### 条件字段（condition ≠ 0）
```
condition = -255:  跳过整个字段（废弃/平台差异）
condition = N > 0: 检查 switch 字段值，匹配时读取
  读取：
    ReadInt index    // switch 字段索引
    ReadInt n        // 匹配值数量
    n * ReadInt args // 允许的值列表
```

### 4.3 关键结构体参考

#### `selectRoleStruct` [id=10001]（角色选择信息）
```
  id          type=0x07  long    // 角色 ID
  name        type=0x0a  string  // 角色名
  sex         type=0x02  byte    // 性别

  level       type=0x04  ushort  // 等级
```

## 5. 登录握手流程

### 5.1 完整流程

```
客户端                       服务器
  │                            │
  │  ① HTTP GET infoURL        │
  │───────────────────────────▶│  PHP 配置服
  │◀───────────────────────────│  返回: cdnURL, loginURL 等
  │                            │
  │  ② HTTP GET entryURL      │
  │───────────────────────────▶│  CDN
  │◀───────────────────────────│  返回: CDN.json（版本信息）
  │                            │
  │  ③ 下载资源（CDN）         │
  │                            │
  │  ④ HTTP GET lastServerList │
  │───────────────────────────▶│  PHP 配置服
  │◀───────────────────────────│  返回: 服务器列表 + sdkParams
  │                            │
  │  ⑤ HTTP GET serverZoneURL │
  │───────────────────────────▶│  PHP 配置服
  │◀───────────────────────────│  返回: 大区信息
  │                            │
  │  ⑥ SDK 登录（平台相关）    │
  │                            │
  │  ⑦ TCP Connect (ip:port)  │
  │═══════════════════════════▶│  Game Server
  │                            │
  │  ⑧ TCP 255_1 (登录请求)   │
  │═══════════════════════════▶│
  │◀═══════════════════════════│  255_1 (登录结果 code=0)
  │                            │
  │  ⑨ TCP 255_5 (角色请求)   │
  │═══════════════════════════▶│
  │◀═══════════════════════════│  255_5 (角色列表)
  │                            │
  │  ⑩ TCP 255_1 (选角进入)   │
  │═══════════════════════════▶│
  │◀═══════════════════════════│  255_1 (入场成功)
  │                            │
```

### 5.2 HTTP 配置响应示例（PHP 配置服）

```json
{
  "cdnURL": "https://cdn.example.com/game/",
  "cdnVersion": 12345,
  "loginURL": "https://login.example.com/auth",
  "serverZoneURL": "https://api.example.com/zone",
  "lastServerListURL": "https://api.example.com/lastserver",
  "serverListURL": "https://api.example.com/serverlist",
  "noticeURL": "https://api.example.com/notice",
  "roleListURL": "https://api.example.com/rolelist",
  "chid": 1,
  "pfid": 100
}
```

### 5.3 服务器列表格式

```
服务器条目编码为固定格式字符串：
  {name}{server_id}{ip}{port}{status}

例：
  {trunk测试服}{290001}{175.178.92.230}{9003}{0}
  {release测试服}{290003}{175.178.92.230}{9006}{0}
```
